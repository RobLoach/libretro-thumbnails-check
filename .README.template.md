## Reports

Each system links to `out/<system>.txt`, which lists every game in the database and whether it has a boxart, snap, title and logo thumbnail. Thumbnails that don't match any game are listed in `out/<system> Orphans.txt`, usually from a misnamed or renamed game.

Thumbnails that RetroArch can never load are listed in `out/<system> Invalid.txt`, and counted in the Invalid column. These are files without a lowercase `.png` extension, names with a character RetroArch replaces with `_` (``&*/:`<>?\|"``), empty or tiny files, files in folders other than `Named_Boxarts`, `Named_Snaps`, `Named_Titles` and `Named_Logos`, and symlinks pointing at a missing file. Symlink targets are fetched with the GitHub GraphQL API and cached in `.cache/symlinks.json`.

The thumbnail lists are fetched fresh on every run from the system repositories in the [libretro-thumbnails](https://github.com/libretro-thumbnails) GitHub organization. Systems without a thumbnail repository are marked "No thumbnails repo" and left out of the total. Only some systems have logos, so the Logos column is left out of the total and percent, and shows "-" for systems without a `Named_Logos` folder.

## Usage

Requires [Node.js](https://nodejs.org) 18 or later, and a GitHub token from the `GITHUB_TOKEN` environment variable or the [GitHub CLI](https://cli.github.com) (`gh auth login`).

```
git clone https://github.com/RobLoach/libretro-thumbnails-check.git
cd libretro-thumbnails-check
make
```

`make` initializes the libretro-database submodule, runs `npm install`, and generates the report. `make clean` removes the generated output and `node_modules`.

To run the report directly:

```
npm run report
```

Pass `--system "<name>"`, once per system, to only check those systems, for example `npm run report -- --system "Atari - 2600" --system "MrBoom"`. The README table is then built from just those systems. The command exits with a non-zero code if any system's thumbnail list fails to fetch.

## Tests

```
npm test
```

Runs the unit tests with the built-in Node.js test runner. They don't need the network, a GitHub token or the libretro-database submodule.
